# Support

Use the channel that matches the kind of help you need. Never post credentials,
personal data, private flow documents, signing keys, or undisclosed
vulnerabilities on a public surface.

<!-- section:usage-questions -->

## Usage questions

Read the [README](README.md), [field reference](docs/SPEC.md), and
[compatibility profiles](docs/COMPATIBILITY.md) first. Use
[GitHub Discussions](https://github.com/wllsena/flowspec2/discussions) for
questions about authoring, integration, or expected behavior that are not
reproducible defects.

<!-- /section:usage-questions -->
<!-- section:bug-reports -->

## Bug reports

Use the repository's
[bug report form](https://github.com/wllsena/flowspec2/issues/new?template=bug_report.yml)
for reproducible defects. Include the flowspec2 version, a minimal sanitized
flow or command, the observed diagnostic, expected behavior, and relevant
environment details. Search existing issues before filing a duplicate.

<!-- /section:bug-reports -->
<!-- section:security-reports -->

## Security reports

Follow [SECURITY.md](SECURITY.md) and use
[private vulnerability reporting](https://github.com/wllsena/flowspec2/security/advisories/new).
Do not disclose a suspected vulnerability in an issue or discussion.

<!-- /section:security-reports -->
<!-- section:support-scope -->

## Support scope

flowspec2 is community-maintained software without a service-level agreement.
Maintainers prioritize reproducible defects, security reports, compatibility
regressions, and bounded proposals that preserve the documented contracts.
Deployment-specific integrations and private flow design remain the operator's
responsibility.
